# Update: rig v2 (2026-09-19)

**From:** `pi-kiosk-v1` → **To:** `feat/rig-v2` (not yet merged to `main`)
UI commits: thesis_ui `pi-kiosk-v1..feat/rig-v2` · Backend commits: `pi-kiosk-v1..feat/rig-v2`

This note ships on branch `feat/rig-v2` in both repos. Once merged to `main`,
use the "After merge" commands below on the Pi; until then, use the
"Testing the branch before merge" block.

## What changed
- Cameras: left/right/back/face are ESP32-S3 USB webcams with fixed names `/dev/aero-*`.
- Calibration shows all four cameras live. Freeze a frame, then draw.
- Live detection models are fixed per camera: front = flying shuttle + pose, sides/back = landed shuttle.
- Registration uses the USB face camera (Wi-Fi ESP32-CAM retired). Upload still works.
- The scoreboard runs on the second monitor (`/#/scoreboard`); the touchscreen keeps the app.
- Servos: each shot aims at the engine's random zone using that zone's calibrated angles ± jitter.

## Before you update: hardware
1. Flash the four boards (`firmware/README.md`), label them, and plug them into a **powered** USB hub on the Pi. Connect each board's native USB port.
2. Flash `servo_aim.ino` to the Arduino, wire the servos (D9 = X, D10 = Y, separate 5-6 V supply), and plug it into the Pi.
3. Connect the second monitor.

## Firmware
The camera board firmware and its `sdkconfig.role` files live in
`firmware/` — see `firmware/README.md` for how to flash each role (left,
right, back, face). Prebuilt binaries are also published as the
`aero-uvc-bins` artifact from the "firmware" GitHub Actions workflow in
`moi-script/machine_vision`, if you'd rather not build locally.

## Commands on the Pi

### After merge to main (normal path)
```bash
cd /opt/aerosense
sudo -u aerosense git fetch --all --tags
sudo -u aerosense git checkout main && sudo -u aerosense git pull && sudo -u aerosense git lfs pull
sudo -u aerosense /opt/aerosense/setup/.venv/bin/pip install "pyserial>=3.5"
sudo bash setup/deploy/install.sh      # udev rules, video/dialout groups, xrandr/xinput, displays.conf
sudo reboot                            # group membership + the new kiosk script need a fresh login
```

### Testing the branch before merge (alternative)
```bash
cd /opt/aerosense
sudo -u aerosense git fetch origin
sudo -u aerosense git checkout feat/rig-v2 && sudo -u aerosense git pull && sudo -u aerosense git lfs pull
sudo -u aerosense /opt/aerosense/setup/.venv/bin/pip install "pyserial>=3.5"
sudo bash setup/deploy/install.sh
sudo reboot
```
(The Pi's remote is named `origin` because it cloned `machine_vision` directly — there is no separate `machine_vision` remote on the Pi itself.)

## Verify
- [ ] `ls -l /dev/aero-*` lists aero-left, aero-right, aero-back, aero-face, aero-servo
- [ ] `systemctl status aerosense` is active; `curl -s localhost:8000/api/aim/health` shows `"connected": true`
- [ ] Touchscreen shows the app; the second monitor shows "Waiting for session"
- [ ] Cameras → Calibrate: 4 live tiles; Freeze & draw works on each
- [ ] Cameras → Live: set front to the OV9281 by-id and left/right/back to /dev/aero-*; Start each; front shows boxes + skeleton, the others show landed-shuttle boxes
- [ ] Players → Register: "face camera online", live preview, Capture enrolls
- [ ] Settings → Aim calibration: each zone moves the servos; set all six; Save
- [ ] Start a medium session: every 3 s the servos move to a different spot; the scoreboard ring resets and the zone lights up
- [ ] Front fps on Cameras → Live. If the front camera is under ~3 fps with both models, set `FRONT_ALTERNATE = True` in `setup/config/settings.py` and restart
- [ ] Check-in on the OV9281: if known players aren't recognised, lower Settings → Detection → face match threshold to ~0.30
- [ ] Each Chromium window lands on its own monitor. If both land on one screen, set `APP_OUTPUT`/`SCOREBOARD_OUTPUT` in `/etc/aerosense/displays.conf` (see "Screens and servo" in `PI-SETUP.md`)
- [ ] ESP32 camera stream smoothness — if a board's stream stutters, reflash it with a lower fps or higher jpeg_quality number in its `sdkconfig.role` file (`firmware/README.md`)
- [ ] If the servo shows "not connected": `ls -l /dev/aero-servo`, and confirm the Arduino is a Nano/Uno with a CH340 or FTDI USB chip (the udev rules match on those VID:PIDs). The backend retries the port every 10 s, so it will pick it up once the device node appears.

## Roll back
```bash
cd /opt/aerosense
sudo -u aerosense git fetch --tags && sudo -u aerosense git checkout pi-kiosk-v1 && sudo -u aerosense git lfs pull
sudo systemctl restart aerosense && sudo -u aerosense pkill chromium
```
The database needs no changes: rig v2 only added fields, which v1 ignores. The udev rules and the extra groups are harmless under v1. The old `kiosk-launch.sh` comes back with the checkout and runs a single window.
